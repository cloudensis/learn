# cloudensis learn

ソフトウェア開発をゼロから学びはじめる人のための無料の学習教材です。

## 対象

ソフトウェア開発の知識がまったくない大学1年生をメインのペルソナとする。
高校生や、ソフトウェアの知識を仕事に活かしたい社会人も想定するが、書き方に迷ったらメインのペルソナで判断する。

## 目的

この教材を離れたあとも、AIを学習パートナーとしてソフトウェア開発を独学で進められる状態になること。

## 目標

1. 次に何を学ぶかを、自分で決められる
2. 分からないことをAIに聞き、返ってきた答えの正しさを自分で確かめられる
3. 詰まったときに、原因の場所を切り分けてAIに相談できる

## 設計

### 設計の基本方針

- **知識ではなく、学び方を身につける教材にする。**
- **AIを使う前提で設計する。**
- **読むより、手を動かす。**

### 目標ごとの設計

#### 目標1:次に何を学ぶかを、自分で決められる

**身につける力**

- ソフトウェア開発の全体像の中で、いま学んでいることがどこに位置するかを説明できる
- 作りたいものから逆算して、必要な知識と学ぶ順番を、理由をつけて決められる

**学習活動**

- 冒頭で、ソフトウェア開発の「地図」を示し、いまどこにいるのかが分かるようにする。
- 教材の後半では、次の単元を複数の選択肢から学習者自身が選ぶ構成にする。

**到達の確認**

- 作りたいものを一つ決め、必要な知識の一覧と学ぶ順番を、理由つきで書き出せる

#### 目標2:分からないことをAIに聞き、返ってきた答えの正しさを自分で確かめられる

**身につける力**

- 分からないことを、AIが答えやすい形の質問にできる(目的、前提、試したことを添える)
- AIの答えを、実際に動かした結果と、公式ドキュメントなどの一次情報の2つで確かめられる
- AIの答えが間違っていたり古かったりすることがある、と実感を持って理解している

**学習活動**

- 「聞く → 確かめる」の型を早い段階で示し、以降の全単元で使う。

**到達の確認**

- 初めて見る題材について、AIに質問し、得た答えを2つ以上の手段で確かめた過程を説明できる

#### 目標3:詰まったときに、原因の場所を切り分けてAIに相談できる

**身につける力**

- 期待した動きと実際の動きの違いを、エラーメッセージから読み取った手がかりとあわせて説明できる
- 問題を再現し、範囲を狭めていく手順を踏める(一部を消す・戻す・分けて試す)
- 切り分けた結果をもとに、要点を絞った相談をAIにできる

**学習活動**

- 読者自身が作っているものに起きた不具合を題材に、「エラー相談の型」を使わせる。

**到達の確認**

- 初めて見る不具合について、原因がありそうな範囲を絞り込み、テンプレートに沿った相談文を書ける

## 編集方針

コンテンツを書くときの決まりごと。**特に 2 と 3 が、従来の教材との差になる。**

1. **章は1回で読み切れる大きさにし、必ず成果物を残す**
   読むだけで終わる章は作らない。各章に「ゴール・手に入るもの・目安時間」を明示する。

2. **画面の手順とスクリーンショットで埋めない**
   サービスの画面は数か月で変わり、手順で埋めた教材はそのたびに使えなくなる。書くのは**何を達成したいか**だけにして、具体的な操作は読者がAIに聞く形にする。そのためのプロンプトを本文に置く。

3. **コードの全文を載せない**
   載せるのは「何をAIに頼むか」と「返ってきたものをどう確かめるか」。写経させる教材にはしない。

4. **AIの答えを検証する手段を必ずセットで渡す**
   初学者はAIの誤りを判定できない。「実際に動かす」「公式の資料で確かめる」の2つを、繰り返し使わせる。

5. **プロンプトは、コピーしてそのまま送れる形で書く**
   穴埋め（`（　）`）は読者ごとに値が違う箇所だけにとどめ、それ以外は完成した文を書いて「書き換えてもよい」と添える。

6. **同じ質問の型を全編で反復する**
   毎回ちがう聞き方を教えるのではなく、下記の型を繰り返し使わせて刷り込む。

7. **本文は敬体で書き、専門用語には初出時に必ず一言添える**

### 繰り返し使う「型」

| 型                   | 用途                                           |
| -------------------- | ---------------------------------------------- |
| 型1・全体像を聞く    | 迷子になったとき、最初に地図をもらう           |
| 型2・部分を聞く      | 気になった一点だけを、範囲を区切って掘る       |
| 型3・理由を聞く      | 選択肢と判断の基準を手に入れる                 |
| エラー相談の型       | やったこと・期待・実際・エラー全文を揃えて渡す |
| 公式資料を参照させる | AIに公式ドキュメントの場所を教えてから質問する |

「公式資料」は、たとえば Cloudflare なら `https://developers.cloudflare.com/workers/llms.txt` を先に開かせてから質問させる形を指す。

## コンテンツの種類

|      | article                                | book                                            |
| ---- | -------------------------------------- | ----------------------------------------------- |
| 形式 | 単発の記事                             | 章立て。順に進む                                |
| 内容 | ツールの使い方など、賞味期限の短いもの | 概念と判断基準など、賞味期限の長いもの          |
| URL  | `/articles/<slug>`                     | `/books/<slug>`、章は `/books/<slug>/<chapter>` |

## 開発

```sh
npm install
npm run dev        # 開発サーバー
npm run lint       # Biome
npm run format     # 自動修正
npm run typecheck  # 型エラーチェック
npm run build      # 本番ビルド

```

デプロイは GitHub の Release 公開をトリガーに、GitHub Actions から Cloudflare Workers へ行われます。
