# cloudensis learn

ソフトウェア開発者のための、無料の学習教材です。

## 対象

ゼロから学びはじめる人から、現役のソフトウェア開発者までを想定する。

読者のフェーズはさまざまだが、ここに来る場面は共通している。**次に何をすればいいか迷ったとき**である。
どのフェーズの読者に、どこまでの深さで書くかは、book / article ごとに決める。

## 目的

この教材を離れたあとも、AIを学習パートナーとしてソフトウェア開発を独学で進められる状態になること。

一度読んで終わりにするものではなく、迷うたびに戻ってこられる場所にする。

## 目標

1. 次に何を学ぶかを、自分で決められる
2. 分からないことをAIに聞き、返ってきた答えの正しさを自分で確かめられる
3. 詰まったときに、原因の場所を切り分けてAIに相談できる

すべてのコンテンツが3つを扱う必要はない。どの目標をどう扱うかは book / article ごとに決め、その設計は各コンテンツの側に書く。

## 設計の基本方針

- **知識ではなく、学び方を身につける教材にする。**
- **AIを使う前提で設計する。**
- **読むより、手を動かす。**

## 編集方針

コンテンツを書くときの決まりごと。**特に 2 と 3 が、従来の教材との差になる。**

1. **章は1回で読み切れる大きさにし、必ず成果物を残す**
   読むだけで終わる章は作らない。各章に「ゴール・手に入るもの・目安時間」を明示する。

2. **画面の手順とスクリーンショットで埋めない**
   サービスの画面は数か月で変わり、手順で埋めた教材はそのたびに使えなくなる。書くのは**何を達成したいか**だけにして、具体的な操作は読者がAIに聞く形にする。そのためのプロンプトを本文に置く。

3. **コードの全文を載せない**
   載せるのは「何をAIに頼むか」と「返ってきたものをどう確かめるか」。写経させる教材にはしない。

4. **AIの答えを検証する手段を必ずセットで渡す**
   読者はAIの誤りを判定できるとは限らない。「実際に動かす」「公式の資料で確かめる」の2つを、繰り返し使わせる。

5. **プロンプトは、コピーしてそのまま送れる形で書く**
   穴埋め（`（　）`）は読者ごとに値が違う箇所だけにとどめ、それ以外は完成した文を書いて「書き換えてもよい」と添える。
   パソコンの種類のように選択肢が決まっている値は、穴埋めにせず `{{os}}` のように書く。プロンプトの上に切り替えが表示され、選んだ値はページをまたいで保存される（選択肢は `src/domains/preference/preference.ts` に定義する）。

6. **同じ聞き方を全編で反復する**
   毎回ちがう聞き方を教えるのではなく、下記の聞き方を繰り返し使わせて刷り込む。
   聞き方には番号を振らず、名前だけで使う場面が分かるようにする。本文で参照するときは「第4章の「選び方を聞く」」のように章番号と名前をセットにし、初めて教えた箇所へリンクする。

7. **本文は敬体で書き、専門用語には初出時に必ず一言添える**
   どこまでを専門用語とみなすかは、そのコンテンツの対象読者で判断する。

### 繰り返し使う聞き方

| 聞き方             | 用途                                           |
| ------------------ | ---------------------------------------------- |
| 一点だけ聞く       | 気になった一点だけを、範囲を区切って掘る       |
| 全体像を聞く       | 迷子になったとき、最初にロードマップをもらう   |
| 選び方を聞く       | 選択肢と判断の基準を手に入れる                 |
| エラーを相談する   | やったこと・期待・実際・エラー全文を揃えて渡す |
| 公式資料を読ませる | AIに公式ドキュメントの場所を教えてから質問する |

「公式資料」は、たとえば Cloudflare なら `https://developers.cloudflare.com/workers/llms.txt` を先に開かせてから質問させる形を指す。

## コンテンツの種類

|      | article                                | book                                            |
| ---- | -------------------------------------- | ----------------------------------------------- |
| 形式 | 単発の記事                             | 章立て。順に進む                                |
| 内容 | ツールの使い方など、賞味期限の短いもの | 概念と判断基準など、賞味期限の長いもの          |
| URL  | `/articles/<slug>`                     | `/books/<slug>`、章は `/books/<slug>/<chapter>` |

book は対象読者とゴールを1冊ごとに定める。冒頭で対象を明示し、その読者に必要な深さで書く。
各 book の設計は、その book のフォルダの README（例：`src/interfaces/routes/books/first-steps/README.md`）に書く。

## 開発

```sh
npm install
npm run dev        # 開発サーバー
npm run lint       # Biome
npm run format     # 自動修正
npm run typecheck  # 型エラーチェック
npm run build      # 本番ビルド
```

デプロイは GitHub の Release 公開をトリガーに、GitHub Actions から Cloudflare Workers へ行われます。
