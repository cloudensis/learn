# cloudensis learn

ソフトウェア開発者のための無料の学習サイトです。

このリポジトリは、サイトの実装とコンテンツの両方を含みます。コンテンツを書き足す前に、以下の設計方針に目を通してください。

## この教材が前提にしていること

初学者が「Reactとは何か」を知りたいとき、いちばん速いのはチャットAIに聞くことです。**網羅的な解説で競っても意味がありません。**

そこでこの教材は、AIが原理的に提供しにくい4つに絞って価値を置きます。

1. **順番** — 何を、どの順で学び、どこで切り上げるか
2. **判断の基準** — 「どれが正解か」ではなく「どういうときにどちらを選ぶか」
3. **つまずきの現場知** — 人が止まるのは成功ルートではなく、分岐と失敗
4. **到達の証明** — 手元に動くものが残り、自分に何ができるようになったか分かること

ゴールは知識の伝達ではなく、**読者を独学に離陸させること**です。教材を閉じたあとも、AIと一緒に自分で進んでいける状態を目指します。

## 対象読者

- **メイン**：ソフトウェア開発の知識がまったくない大学1年生
- そのほか：高校生、ソフトウェア業界への転職を考えている社会人、自社の業務にソフトウェアの知識を活かしたい社会人

サイト全体としては「仕事にできるところまで」を目指しますが、**1冊ごとに到達点を刻みます**。1冊で全部を教えようとしません。

## 編集方針

コンテンツを書くときの決まりごとです。**特に 2 と 3 が、従来の教材との差になります。**

1. **章は1回で読み切れる大きさにし、必ず成果物を残す**
   読むだけで終わる章は作りません。各章に「ゴール・手に入るもの・目安時間」を明示します。

2. **画面の手順とスクリーンショットで埋めない**
   サービスの画面は数か月で変わり、手順で埋めた教材はそのたびに使えなくなります。書くのは**何を達成したいか**だけにして、具体的な操作は読者がAIに聞く形にします。そのためのプロンプトを本文に置きます。

3. **コードの全文を載せない**
   載せるのは「何をAIに頼むか」と「返ってきたものをどう確かめるか」です。写経させる教材にはしません。

4. **AIの答えを検証する手段を必ずセットで渡す**
   初学者はAIの誤りを判定できません。「実際に動かす」「公式の資料で確かめる」の2つを、繰り返し使わせます。

5. **プロンプトは、コピーしてそのまま送れる形で書く**
   穴埋めの記法（`（　）`）を使うのは、読者ごとに値が違って当然の箇所（使える学習時間、OSの種類など）だけにします。好みで変えられる箇所は、完成した文を書いたうえで「書き換えてもよい」と添えます。

6. **同じ質問の型を全編で反復する**
   毎回ちがう聞き方を教えるのではなく、下記の型を繰り返し使わせて刷り込みます。

7. **賞味期限で置き場所を分ける**
   腐りやすい記述（ツールの画面、手順）は article に置き、book には概念と判断基準だけを書いて article へリンクします。本体が長持ちします。

8. **敬体で書き、専門用語には初出時に必ず一言添える**

### 繰り返し使う「型」

| 型                       | 用途                                           |
| ------------------------ | ---------------------------------------------- |
| 型1・全体像を聞く        | 迷子になったとき、最初に地図をもらう           |
| 型2・部分を聞く          | 気になった一点だけを、範囲を区切って掘る       |
| 型3・理由を聞く          | 選択肢と判断の基準を手に入れる                 |
| 型4・採点させる          | 自分の言葉で説明し、分かったつもりを見つける   |
| エラー相談の型           | やったこと・期待・実際・エラー全文を揃えて渡す |
| 公式資料を参照させる呪文 | AIに公式ドキュメントの場所を教えてから質問する |

「呪文」は、たとえば Cloudflare であれば `https://developers.cloudflare.com/workers/llms.txt` を先に開かせてから質問させる形を指します。画面の手順を本文に書かずに済ませる仕掛けであり、読了後も使える技術でもあります。

## コンテンツの種類

|      | article                                | book                                            |
| ---- | -------------------------------------- | ----------------------------------------------- |
| 形式 | 単発の記事                             | 章立て。順に進む                                |
| 内容 | ツールの使い方など、賞味期限の短いもの | 概念と判断基準など、賞味期限の長いもの          |
| URL  | `/articles/<slug>`                     | `/books/<slug>`、章は `/books/<slug>/<chapter>` |

book は Zenn の「本」と同じ概念で、**このサイトが提供するコンテンツ**です。外部の書籍を紹介するものではありません。

## 公開中のコンテンツ

### 本「AIとつくる、はじめてのWebアプリ公開」（全7章・約7時間・費用0円）

プログラミング未経験者が、AIとWebアプリを作り、Cloudflare Workers に公開し、その仕組みを理解するまで。

| #    | 章                       | 手に入るもの                           |
| ---- | ------------------------ | -------------------------------------- |
| 序章 | この本の歩き方           | 使うAIを決めて、最初の質問を投げた状態 |
| 1    | AIにアプリを作ってもらう | ブラウザで動くHTMLファイル             |
| 2    | 世界に公開する           | 自分の公開URL                          |
| 3    | いま何が起きているのか   | 自分のアプリを観察した記録             |
| 4    | 自分のパソコンで開発する | ローカル開発環境と、動的なページ       |
| 5    | 壊して直す               | 3つの故障を自分で直した経験            |
| 6    | この先をAIと歩く         | AIと作った学習計画                     |

設計上の要点は3つです。

- **第2章までで公開URLが手に入る**（約2.5時間）。環境構築を先に置くと、そこで脱落します
- **第3章は解説を読ませず、自分のアプリを観察させる**。5つの実験で確かめます
- **第5章「壊して直す」を必ず通す**。AI時代の初学者の弱点は知識不足ではなく、壊れたときに手が出せないことです

### 記事

- チャットAIの組み込み機能（Canvas / Artifacts）だけでブラウザゲームを作って共有する
- 【初学者向け】Google AI Studioでwebアプリを作ってみよう

## 実装

Hono + Cloudflare Workers。ルーティングは `src/index.tsx` が `src/interfaces/routes/**/index.tsx` を自動で読み込むため、フォルダを置くだけで公開されます。

```
src/
├── domains/
│   ├── article/article.ts      Article 型
│   ├── book/book.ts            Book / BookChapter 型、chapterLabel、totalMinutes
│   └── company/constants.ts    サイト名・URL・説明
├── interfaces/
│   ├── middleware/renderer.tsx  共通レイアウトとメタタグ
│   └── routes/
│       ├── template.tsx         ホーム
│       ├── _components/         記事一覧・本一覧
│       ├── articles/
│       │   ├── registry.ts      各記事の meta.ts を自動収集
│       │   └── <slug>/          meta.ts / index.tsx / template.tsx
│       └── books/
│           ├── registry.ts      各本の meta.ts を自動収集
│           ├── _components/     章で使う共通パーツ
│           └── <slug>/
│               ├── meta.ts      本のメタ情報
│               ├── chapters.ts  各章の meta.ts を自動収集
│               ├── index.tsx    目次ページのルート
│               ├── template.tsx 目次ページ
│               └── chapters/<slug>/  meta.ts / index.tsx / template.tsx
```

### 章で使う共通パーツ

`src/interfaces/routes/books/_components/` にあります。

- `ChapterHeader` — 章の冒頭。ゴール・手に入るもの・目安時間
- `AskAi` — AIに送るプロンプト。クリックで全選択できます
- `Checklist` — 章末の到達確認
- `Troubleshoot` — つまずきと対処
- `ChapterList` / `ChapterNav` — 目次と、前後の章へのリンク

`BookChapter` に `goal` / `deliverable` / `estimatedMinutes` を必須で持たせているのは、編集方針1を型で強制するためです。**確認チェックリストを書けない章は、ゴールが曖昧な章**だと気づけます。

### 記事を追加する

`src/interfaces/routes/articles/<slug>/` に3つのファイルを置くだけです。一覧への反映は自動です。

- `meta.ts` — `Article` 型のメタ情報（`slug` / `title` / `description` / `publishedAt` / `ogp?`）
- `index.tsx` — ルート定義
- `template.tsx` — 本文

画像は `public/articles/<slug>/` に置きます。

### 本・章を追加する

本は `src/interfaces/routes/books/<slug>/`、章はその下の `chapters/<slug>/` に置きます。章の `meta.ts` に `number` を書けば、その順で目次に並びます。序章は `number: 0` です。

## 開発

```sh
npm install
npm run dev        # 開発サーバー
npm run lint       # Biome
npm run format     # 自動修正
npm run typecheck  # 型エラーチェック
npm run build      # 本番ビルド

```

デプロイは GitHub の Release 公開をトリガーに、GitHub Actions から Cloudflare Workers へ行われます。
