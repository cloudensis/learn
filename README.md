# cloudensis learn

ソフトウェア開発者のための無料の学習サイトです。

## 目的

AIを学習パートナーとして、ソフトウェア開発を独学で学んでいける状態を目指す。

## 対象

ソフトウェア開発の知識がまったくない大学1年生をメインのペルソナとする。
そのほかに、高校生、ソフトウェア業界への転職を考えている社会人、自社の業務にソフトウェアの知識を活かしたい社会人なども想定する。

## 設計

AIを学習パートナーとして独学で学ぶための最初の入口をつくる。
ロードマップと、学習にAIを活用する方法を提供する。
バイブコーディングは目指さない。

- ロードマップを示す。
  - 基礎から仕事として働ける水準を目指す。
  - それ以降は独学で新しい技術にもキャッチアップできる状態を目指す。
- 知識部分はAIに解説させるプロンプトとして提供する。
  - 最新の情報も反映させられる。
  - 分からない部分はすぐに質問できる。
- 詰まった時のAIへの質問の仕方、AIを使ってソフトウェアを改善する方法を提供する。
  - エラーや環境など、コンテキストを整理して渡す方法を示す。
  - どこにどの程度負荷がかかるアプリケーションか、セキュリティ要件はどの程度満たせば良いかなど、AIと一緒に適切な設計、改修をする方法を示す。

## 編集方針

コンテンツを書くときの決まりごと。**特に 2 と 3 が、従来の教材との差になる。**

1. **章は1回で読み切れる大きさにし、必ず成果物を残す**
   読むだけで終わる章は作らない。各章に「ゴール・手に入るもの・目安時間」を明示する。

2. **画面の手順とスクリーンショットで埋めない**
   サービスの画面は数か月で変わり、手順で埋めた教材はそのたびに使えなくなる。書くのは**何を達成したいか**だけにして、具体的な操作は読者がAIに聞く形にする。そのためのプロンプトを本文に置く。

3. **コードの全文を載せない**
   載せるのは「何をAIに頼むか」と「返ってきたものをどう確かめるか」。写経させる教材にはしない。

4. **AIの答えを検証する手段を必ずセットで渡す**
   初学者はAIの誤りを判定できない。「実際に動かす」「公式の資料で確かめる」の2つを、繰り返し使わせる。

5. **プロンプトは、コピーしてそのまま送れる形で書く**
   穴埋めの記法（`（　）`）を使うのは、読者ごとに値が違って当然の箇所（使える学習時間、OSの種類など）だけにする。好みで変えられる箇所は、完成した文を書いたうえで「書き換えてもよい」と添える。

6. **同じ質問の型を全編で反復する**
   毎回ちがう聞き方を教えるのではなく、下記の型を繰り返し使わせて刷り込む。

7. **賞味期限で置き場所を分ける**
   腐りやすい記述（ツールの画面、手順）は article に置き、book には概念と判断基準だけを書いて article へリンクする。本体が長持ちする。

8. **本文は敬体で書き、専門用語には初出時に必ず一言添える**

### 繰り返し使う「型」

| 型                       | 用途                                           |
| ------------------------ | ---------------------------------------------- |
| 型1・全体像を聞く        | 迷子になったとき、最初に地図をもらう           |
| 型2・部分を聞く          | 気になった一点だけを、範囲を区切って掘る       |
| 型3・理由を聞く          | 選択肢と判断の基準を手に入れる                 |
| 型4・採点させる          | 自分の言葉で説明し、分かったつもりを見つける   |
| エラー相談の型           | やったこと・期待・実際・エラー全文を揃えて渡す |
| 公式資料を参照させる呪文 | AIに公式ドキュメントの場所を教えてから質問する |

「呪文」は、たとえば Cloudflare であれば `https://developers.cloudflare.com/workers/llms.txt` を先に開かせてから質問させる形を指す。画面の手順を本文に書かずに済ませる仕掛けであり、読了後も使える技術でもある。

## コンテンツの種類

|      | article                                | book                                            |
| ---- | -------------------------------------- | ----------------------------------------------- |
| 形式 | 単発の記事                             | 章立て。順に進む                                |
| 内容 | ツールの使い方など、賞味期限の短いもの | 概念と判断基準など、賞味期限の長いもの          |
| URL  | `/articles/<slug>`                     | `/books/<slug>`、章は `/books/<slug>/<chapter>` |

book は Zenn の「本」と同じ概念で、**このサイトが提供するコンテンツ**。外部の書籍を紹介するものではない。

## 公開中のコンテンツ

### 本「AIとつくる、はじめてのWebアプリ公開」（全7章・約7時間・費用0円）

プログラミング未経験者が、AIとWebアプリを作り、Cloudflare Workers に公開し、その仕組みを理解するまで。

| #    | 章                       | 手に入るもの                           |
| ---- | ------------------------ | -------------------------------------- |
| 序章 | この本の歩き方           | 使うAIを決めて、最初の質問を投げた状態 |
| 1    | AIにアプリを作ってもらう | ブラウザで動くHTMLファイル             |
| 2    | 世界に公開する           | 自分の公開URL                          |

## 開発

```sh
npm install
npm run dev        # 開発サーバー
npm run lint       # Biome
npm run format     # 自動修正
npm run typecheck  # 型エラーチェック
npm run build      # 本番ビルド

```

デプロイは GitHub の Release 公開をトリガーに、GitHub Actions から Cloudflare Workers へ行われます。
